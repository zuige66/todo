## 四、为什么用合规分支的代码

`main` 分支含应用内「检查更新」，需 INTERNET 权限；`release/vivo-store` 已删除自更新、未申请网络权限、`allowBackup=false`。
软著材料与隐私政策必须一致——若提交 main 的代码，材料里会出现联网检测更新，与政策中「不申请网络权限」直接冲突。故本次全部材料以合规分支为准。

## 五、版本号的一个提醒

合规分支构建号是 `versionName = 1.0.1`（versionCode 35），本次材料按 `V1.0.2` 出具（用户指定）。
审查不核对 versionName，不影响受理。但**若该证书要用于应用商店资质审核**，建议改为 `V1.0.1` 与在架版本对齐。
改名只需在 `_生成脚本/` 下把各脚本顶部 `VER` 改为 `V1.0.1` 后重跑（见下）。

## 六、重新生成

```bash
# 依赖：python-docx、pywin32；系统装有 Microsoft Word（用于导 PDF）
cd "D:/Workplace/Todo"

# 1. 导出合规分支源码（不污染工作区）
mkdir -p /tmp/cr-src && git archive release/vivo-store | tar -x -C /tmp/cr-src

# 2. 生成图表 PNG（若改了 SVG）
python "output/软著材料/_生成脚本/svg2png.py" "output/软著材料/图表"

# 3. 生成五份 DOCX
cd "output/软著材料/_生成脚本"
python gen_source.py "/tmp/cr-src" "D:/Workplace/Todo/output/软著材料"
python gen_design.py
python gen_manual.py
python gen_doc_ident.py
python gen_form.py
python gen_text.py

# 4. 导 PDF
python to_pdf.py "D:/Workplace/Todo/output/软著材料"
```

> 导 PDF 前先 `taskkill //F //IM WINWORD.EXE`，否则 Word 残留进程会让文档变只读、导出失败。
