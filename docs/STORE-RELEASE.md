## 三、不合规清单

### 🔴 红线 1：应用内自更新（必拒，最高优先级）

**现状**：`AndroidManifest.xml` 声明了 `REQUEST_INSTALL_PACKAGES`，配合
`update/UpdateService.kt`（读 GitHub Releases 版本号）+ `update/UpdateDownloadService.kt`
（下载 APK）+ `update/ApkInstaller.kt`（调起系统安装器）+ 关于页「检查更新」按钮。

**为什么必拒**：国内所有主流商店（vivo / 华为 / 小米 / OPPO / 应用宝）都把
「应用内下载、引导或安装 APK」视为绕过商店分发。vivo 规范 3.1.1 与功能审核条款
明确要求应用不得自行分发安装包；`REQUEST_INSTALL_PACKAGES` 是国内审核的高压线权限。
审核员点开「关于 → 检查更新」看到 GitHub 下载路径，等于自证违规。

**修复方案（三选一）**：

| 方案 | 做法 | 代价 |
|---|---|---|
| A（推荐） | 整体删除自更新：删 4 个文件、移除 4 个权限、去掉「检查更新」入口 | 老用户失去应用内更新，改由商店/博客分发 |
| B | 保留入口，但只跳浏览器到博客下载页 | 仍属「引导安装」，风险中高，不建议 |
| C | 改为跳转应用商店详情页 | 需上架后才有链接，且国内商店对「跳商店」也敏感 |

**A 方案额外收益**：移除 `INTERNET` 后应用变成**纯单机**，
① 备案义务大概率可豁免（工信部备案针对「互联网信息服务」）；
② 隐私政策可以写成「不收集任何信息、不联网」，审核最省事；
③ 应用介绍里「数据全部留在本机」才真正成立（现在有联网，严格说这句话不准确）。

**受影响的文件**：
```
app/src/main/AndroidManifest.xml          （4 个权限 + UpdateDownloadService + FileProvider）
app/src/main/kotlin/.../update/UpdateService.kt
app/src/main/kotlin/.../update/UpdateDownloadService.kt
app/src/main/kotlin/.../update/ApkInstaller.kt
app/src/main/kotlin/.../ui/screen/UpdateDialog.kt
app/src/main/kotlin/.../ui/screen/AboutScreen.kt  （检查更新入口）
app/src/main/res/xml/file_paths.xml
```

### 🔴 红线 2：没有隐私政策

**现状**：全项目 `grep 隐私 / privacy` 只命中文档，**代码里零实现**。
关于页只有「博客 / GitHub / 版本」，没有隐私政策入口，也没有首次启动同意弹窗。

**为什么必拒**：《个人信息保护法》《App 违法违规收集使用个人信息行为认定方法》
要求 App 首次运行时以弹窗等显著方式告知并取得同意；商店审核逐条对照。
即使是「不收集任何信息」的 App，也必须提供隐私政策并让用户确认。

**修复方案**：
1. 关于页新增「隐私政策」入口（打开内嵌页面或外部链接）
2. 首次启动弹窗：标题 + 摘要 + 「查看完整隐私政策」+「同意并继续 / 不同意（退出）」
3. 同意状态存 SharedPreferences，只弹一次
4. 隐私政策正文放到 `blog.zuiges.com` 的静态页（免费，商店要一个 URL）

**本项目隐私政策可以极简**（这是优势，别浪费）：

> 本应用不收集、不上传、不共享任何个人信息。所有待办数据仅保存在您的设备本地。
> 应用不申请通讯录、位置、相机、麦克风、设备标识等权限。
> 卸载应用即删除全部数据。

### 🔴 红线 3：没有 App 备案号

**现状**：关于页无备案号，代码中无任何备案信息。

**要求**：工信部《关于开展移动互联网应用程序备案工作的通知》——
App 主办者应在 App **显著位置标明备案编号，并在编号下方链接备案系统网址**。

**处理顺序**（重要，别搞反）：
1. **先做红线 1**（砍掉联网）→ 变成纯单机
2. 在 vivo 后台创建应用，看「App 备案号」字段是否强制必填
3. 若必填 → 联系 vivo 在线客服，说明「纯单机应用、无互联网信息服务」，按其指引提交说明
4. 若客服仍要求备案 → 走工信部备案（免费，但需接入服务商，见第四节）

### 🟠 高风险 4：应用名「Todo」过不了命名审核

**现状**：`app_name = Todo`，后台若填「Todo」，会撞上 vivo 规范 2.2.3。

> **2.2.3** 应用名称不得仅包含少量普遍、不具辨识性的词汇……包括但不限于
> **类别词、功能词**、商业化词、流行词及前述类型的组合。

「Todo」正是纯功能词，与规范举例的「计算器」「主题壁纸」同类。

**连带约束（必须一起考虑）**：
- **2.2.5** 应用名称须与软著名称一致
- **3.1.4** 软著证书中的应用名称需与上传的应用名称保持一致
- **2.2.9** 每年只能主动改名 4 次，且更名需重新提供对应软著

→ **名称必须在申请软著之前定死**，否则软著白做。

**候选（需先去商店搜是否重名）**：

| 候选 | 字数 | 评价 |
|---|---|---|
| 一句话待办 | 5 | 最贴合产品定位，辨识度够，推荐 |
| 浪花待办 | 4 | 呼应图标（波浪花瓣），品牌感强 |
| 拾句待办 | 4 | 文艺，但功能指向弱一些 |
| Todo 一句话待办 | — | 保留英文名，主副标题，需注意 2.2.2 特殊符号限制 |

**改名影响面**：`strings.xml` 的 `app_name`、软著名称、商店后台名称三处必须一致；
桌面图标文字会变，老用户会感知，但包名 `com.lirui.oneline` 不用改，不影响升级。

### 🟡 需说明项 6：三个「敏感但正当」的权限

提交审核时后台有「权限说明」填写框，逐条写清用途，否则会被打回补充：

| 权限 | 建议填写 |
|---|---|
| USE_EXACT_ALARM / SCHEDULE_EXACT_ALARM | 待办提醒需要在用户设定的精确时刻响铃，非精确闹钟会被系统延迟数分钟，属核心功能 |
| REQUEST_IGNORE_BATTERY_OPTIMIZATIONS | 仅在用户于「提醒可靠性」页主动点击时跳转系统白名单页，用于避免后台被清理导致漏提醒；不在启动时自动弹出 |
| FOREGROUND_SERVICE_SPECIAL_USE | 可选的后台常驻通知（默认关闭），用于及时响应提醒通知上的「完成/撤回」操作，用户可在设置中随时关闭 |

## 四、零成本路径与时间线

### 花钱的地方 vs 免费的地方

| 环节 | 官方价 | 说明 |
|---|---|---|
| vivo 开发者注册 + 个人实名认证 | **免费** | 身份证正反面，1~2 工作日 |
| 应用提交审核 | **免费** | 审核 1~2 工作日 |
| 计算机软件著作权登记 | **免费** | 中国版权保护中心官网，受理起 30 个工作日 |
| App 备案 | **免费** | 工信部政务服务平台 |
| 素材（图标/截图/文案） | **免费** | 自己出 |
| 软著加急 | 收费 | 不必，等就行 |
| App 备案接入商 | **可能要钱** | 阿里云/腾讯云备案需服务器或备案服务码 |

**结论：可以 0 元上架，成本是时间，不是钱。**

### 时间线（从今天 2026-10-25 起算）

```
第 0 天     ── 定应用名 → 改代码（砍自更新 / 加隐私政策 / 改名）
第 1 天     ── 提交软著申请（名称必须已定死）
              ⚠️ 这是最长的一环，务必第一天就交
第 3~5 天   ── 软著受理
第 1 周     ── vivo 开发者注册 + 实名认证通过
              ── 重截 1080×1920 截图、导出无透明图标
              ── 隐私政策页面上线到 blog.zuiges.com
第 2 周     ── 代码改完，出新包（versionCode 34）
              ── 后台创建应用、填素材、存草稿
第 6 周     ── 软著下证（30 个工作日）
第 6~7 周   ── 补软著 + 备案号 → 提交审核
第 7~8 周   ── 审核通过、上架
```

**最快约 12 月中上旬**。卡点只有软著，其他都能并行。

### 软著申请材料（自己办）

1. **申请表**：中国版权保护中心官网（ccopyright.com.cn）在线填写
2. **源程序**：前 30 页 + 后 30 页，每页 50 行，页眉写明软件名称+版本号
   （本项目代码量充足，直接抽取即可）
3. **软件说明书**：用户手册或设计文档，图文并茂，≥30 页为佳
   （可直接用 README + DESIGN.md + 截图改写成 PDF）
4. **身份证明**：身份证正反面
5. 申请人填**本人**（vivo 3.1.5：个人开发者资质须本人持有，不接受授权）

## 五、vivo 申报步骤

1. **注册**：dev.vivo.com.cn → 选择「个人开发者」→ 提交身份证正反面 + 实名认证（1~2 工作日）
2. **创建应用**：
   - 应用名称 = 软著名称 = APK 内 `app_name`（三处必须完全一致）
   - 包名 `com.lirui.oneline`
   - 分类：实用工具 → 效率
   - 资费：免费
3. **上传 APK**：release 签名包，versionCode 必须大于线上版本
4. **填素材**：
   - 图标 512×512 直角、≤500 KB、无透明
   - 截图 3~5 张、1080×1920、竖图统一、≤2 MB
   - 一句话简介 5~16 字
   - 应用介绍 ≥50 字
   - 新版说明 ≥5 字，且 ≠ 应用介绍
5. **填资质**：软著证书扫描件 + App 备案号
6. **填隐私政策 URL**（公网可访问，建议 `blog.zuiges.com/privacy`）
7. **填权限说明**：见第三节第 6 条表格
8. **提交审核**：1~2 工作日

### 审核被拒的常见补充动作
- 权限说明写得含糊 → 逐条重写用途
- 截图分辨率不对 → 重传
- 名称与软著不一致 → 统一
- 隐私政策打不开 → 换稳定链接
- 「应用打开后提示更新版本」→ 已通过红线 1 的修复规避
