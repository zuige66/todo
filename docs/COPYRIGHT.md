## 二、关键决策（都有理由，别随手改）

**1. 代码基线用 `release/vivo-store`，不用 `main`**
★ 2026-11-07 勘误：原先这里写「main 有应用内检查更新、需 INTERNET」，是**过期描述**。
应用内检查更新自 v1.0.0 起已整体下线，**两个分支的 Manifest 都不声明 INTERNET**，
`allowBackup` 也都是 `false`；合规分支另有隐私弹窗与上架文档。
选合规分支做基线是因为软著材料必须跟商店上架包一致，**不是因为网络权限有差异**。
软著材料仍必须与 `docs/PRIVACY.md` 口径一致，否则材料里写「联网检测更新」
而政策写「不申请网络权限」，自己打自己。

**2. 源程序量按 13088 行填，不是 13077**
- `find ... | wc -l` = 13077（按换行符数，11 个文件末尾无换行被少算）
- Python 逐行读 = 13088（真实行数）
取后者。材料里所有出现的数字必须一致，改一处就要全局搜。

**3. 版本号 V1.0.2 与代码 versionName=1.0.1 不一致，是已知偏差**
zuige 指定 V1.0.2。审查不核对 versionName，不影响受理；但若证书要用于应用商店资质审核，
应改为 V1.0.1 与在架版本对齐。改名只需改 `_生成脚本/*.py` 顶部的 `VER` 常量后重跑。

**4. 文档鉴别材料只有 32 页，没强行凑到 60 页**
规范原文是「文档前、后各连续 30 页，**不足 60 页的全部提交**」。32 页交全文合规。
灌水凑页数只会降低材料质量。

**5. 技术特点类别勾 APP；编程语言勾 Java + 其他填 Kotlin**
版权中心的编程语言列表里**没有 Kotlin**。纯 Kotlin 项目若只勾 Java，与源代码材料里的 Kotlin 语法不一致，
审核可能要求补正。

## 四、踩坑记录

**1. `svg_to_png.py`（技能自带）在 Python 3.13 下直接崩**
`open(..., 'wb', encoding=...)` → `ValueError: binary mode doesn't take an encoding argument`。
改用 Edge headless 自写渲染（`_生成脚本/svg2png.py`），包一层 HTML 再截图，`--force-device-scale-factor=2` 出 2 倍图。

**2. Word 导 PDF 报「无法保存此文件，因为它为只读文件」**
两个原因叠加：残留 `WINWORD.EXE` 进程锁住文档；目标 PDF 已存在时 `ExportAsFixedFormat` 覆盖失败。
解法：导前 `taskkill //F //IM WINWORD.EXE`，且脚本内先 `os.remove(pdf)` 再导出，`Documents.Open` 用 `ReadOnly=True`。

**3. 分隔页后面直接接上了代码**
`emit_block` 只在 `i % 50 == 0` 时插分页，后 30 页的第一个块 `i=0` 不触发。
必须在 `emit_block(doc, tail)` 前手动加一个 `add_break(WD_BREAK.PAGE)`。
修完正好 62 页（30 + 1 + 30 + 1）。

**4. `add_break(6)` 不行**
python-docx 的 `add_break` 只认 `WD_BREAK` 枚举，传整数 6 报 `KeyError`。

**5. 截图宽度 7cm 会把半页文字挤到下一页**
A4 可用高 24.6cm，7cm 宽的手机截图约 15.5cm 高，加上图注正好卡在临界。
改 6.2cm 后页数从 23 降到 21，空白消失。
